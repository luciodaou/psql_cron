# PostgreSQL Automated Synchronization Cron (`psql_cron`)

A modern Python and Docker Compose stack managed with [**uv**](https://docs.astral.sh/uv/) that periodically synchronizes and exports PostgreSQL tables/views to JSON and/or CSV files based on configuration files.

Each synchronization supports **multiple independent cron schedules** (`cron.<n>`) directly inside its configuration file.

---

```text
│       ├── export.py        # Atomic JSON and CSV export logic
│       └── scheduler.py     # Multi-schedule engine with per-sync multi-cron evaluation

│   └── example.ini.template # Template for adding new syncs
└── output/                  # Output directory
    └── v_cto_ff.json        # Exported JSON file
```

## Synchronization Configuration (`syncs/<syncname>.ini`)

To add a synchronization, place a file named `<syncname>.ini` inside the `syncs/` directory.

### Example (`syncs/v_cto_ff.ini`)

```ini
database = db_despesas
schema = public
table = v_cto_ff
csv = false
json = true
output_path = ./output
cron.1 = 9,39 7-20 * * 1-5
cron.2 = 30 6 * * 1
```

### Parameter Reference

| Parameter | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `database` | String | **Yes** | Target database name (e.g., `db_despesas`). |
| `schema` | String | No | Database schema name (default: `public`). |
| `table` | String | **Yes** | Table or view name to export (e.g., `v_cto_ff`). |
| `csv` | Boolean | **Yes** | Whether to export as CSV (`true` or `false`). |
| `json` | Boolean | **Yes** | Whether to export as JSON (`true` or `false`). |
| `output_path` | String | **Yes** | Directory where output files will be written. Relative paths like `./output` resolve to `./output` on the host. |
| `cron.<n>` | String | No | Multiple cron schedules (e.g. `cron.1`, `cron.2`, `cron.3`). |
| `cron` | String | No | Single cron schedule (backward-compatible). |

### Multi-Schedule Engine Features

1. **Multiple Crons per Sync**: Define as many `cron.<n>` schedules as needed (e.g., `cron.1 = 9,39 7-20 * * 1-5`, `cron.2 = 30 6 * * 1`). The synchronization triggers whenever **any** of the configured schedules match.
2. **Dynamic Hot-Reloading**: The scheduler continuously monitors `syncs/`. Any addition, modification, or removal of `.ini` files (or their `cron.<n>` schedules) is picked up dynamically without restarting the container.
3. **Collision Avoidance**: If multiple cron rules for the same sync coincide at the exact same minute, the sync executes once, advancing all matching triggers to prevent duplicate work.

## Local Development with `uv`

```bash
# Sync/install virtualenv
uv sync

# Run CLI
uv run psql-cron --help

# Run a one-shot sync cycle
uv run psql-cron --once

# Run the scheduler locally
uv run psql-cron
```

---

## Docker Compose Execution

```bash
# Start background scheduler
docker compose up -d

# View daemon logs
docker compose logs -f

# Run one-shot sync in container
docker compose run --rm psql-cron psql-cron --once

# Stop service
docker compose down
```
